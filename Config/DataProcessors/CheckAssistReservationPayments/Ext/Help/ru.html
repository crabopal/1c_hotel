Обработка "Проверить поступление оплаты по платежной системе Assist"

Назначение

Обработка используется для автоматической проверки поступления оплаты через систему электронных платежей Assist по брони созданной через модуль on-line бронирования. Оплата брони считается просроченной если с момента регистрации брони в программе до момента выполнения обработки прошло кол-во минут больше чем указано в параметре на форме обработки.

В параметрах обработки можно указать:

  • "Статус новой брони созданной модулем on-line бронирования" -- должен быть указан. Модуль on-line бронирования должен быть настроен так, чтобы создавать новую бронь с этим статусом (см. файл current_config.xml, параметр ReservationStatus). Обработка отбирает бронь с этим статусом и далее проверяет просрочена ли оплата по брони, поступил ли платеж по этой брони. 
  • "Статус гарантированной (оплаченной) брони" -- должен быть указан. У брони с полученной оплатой будет установлен этот статус.
  • "Статус брони с просроченной оплатой" -- если указан, то у брони с просроченной оплатой будет установлен этот статус.
  • "Способ оплаты для платежей через Assist" -- должен быть указан. Определяет способ оплаты с которым будут создаваться платежи по лицевым счетам on-line брони.
  • "Время ожидания поступления оплаты по брони в минутах" -- обязательный параметр, определяет количество минут в течение которых программа ожидает поступления оплаты по брони.
  • "Тип отправки сообщения об изменении статуса брони" -- если указан, то после изменения статуса on-line брони, если в брони введен контактный E-Mail или указан номер факса, программа создаст автоматическое сообщение об изменении статуса и подготовит его к отправке клиенту. Открыть и отредактировать сообщение можно по кнопке "Прикрепленные документы" в карточке группы. Отправка сообщений выполняется отдельной регламентной процедурой "Отправить уведомления по группам гостей". Параметр имеет смысл только при заполненных статусах гарантированной и/или просроченной брони. E-Mail и номер факса для отправки сообщения программа берет из карточки главного гостя в группе или, если в карточке гостя эти поля не указаны, из карточки контрагента группы. 
  • "Отдел, сотрудникам которого отправлять сообщения о брони с просроченной оплатой" -- если указан, то по каждой группе с просроченной оплатой будет отправлено внутреннее сообщение сотрудникам из указанного отдела.  
  • "ID магазина в системе Assist" -- ID гостиницы в системе электронных платежей Assist (число)
  • "Логин пользователя в системе Assist" -- Логин гостиницы для доступа к API функциям системы Assist, обычно заканчивается на "_sale".
  • "Пароль пользователя в системе Assist" -- Пароль для доступа к API функциям системы Assist
  • "Кассовая секция платежей" -- Заполняется только в случае, если платежи за бронирование номеров должны проводится по специальной кассовой секции.
  • "Код внешней системы" в системе online бронирования -- Код внешней системы, как он указан в конфигурационном файле модуля онлайн бронирования. См. файл current_config.xml, параметр ExternalSystemCode
  • "Использовать Proxy", логин, пароль для подключения к прокси серверу -- включите, если для доступа в интернет на компьютере, на котором выполняется проверка статусов заказов в системе Assist (фоновое задание), необходимо указать пароль и имя пользователя в интернет прокси

Относится к подсистеме: «Стойка администратора».

Способ вызова

Вызывается из меню "Обработки"

Дополнительная информация

Рекомендуемый режим запуска обработки: фоновое задание с периодичностью запуска каждые 2 или 3 минуты.

Для доступа по протоколу HTTPS к сайту платежной системы Assist необходимо в конец текстового файла с данными корневых сертификатов c:\Program Files\1cv82\8.2.ХХ.ХХХ\bin\cacert.pem вставить блок с сертификатом центра сертификации Thawte. Вставлять блок нужно на том компьютере, с которого будет выполняться проверка статусов заказов в системе Assist.
